## 🎯 OBJETIVO DEL PROYECTO

Desarrollar un sistema inteligente capaz de **clasificar automáticamente algoritmos en categorías de complejidad computacional** (O(1), O(log n), O(n), O(n²), O(2^n)) utilizando:
- **Red Neuronal Multicapa (MLP)** implementada desde cero
- **3 features numéricos** extraídos de análisis estático del código
- **Dataset balanceado** de 144 algoritmos Go

---

## 🏗️ ARQUITECTURA DEL SISTEMA

### 1. Red Neuronal (MLP Custom)
```
Input Layer:    3 features
├─ loops:       Número de bucles anidados (0-5)
├─ recursion:   Booleano (0 o 1)
└─ nested_depth: Profundidad de anidamiento (1-5)

Hidden Layer 1: 64 neurons (ReLU)
Hidden Layer 2: 32 neurons (ReLU)

Output Layer:   5 classes (Softmax)
├─ O(1)        - Complejidad constante
├─ O(log n)    - Búsquedas divide & conquer
├─ O(n)        - Complejidad lineal
├─ O(n²)       - Complejidad cuadrática
└─ O(2^n)      - Complejidad exponencial
```

### 2. Entrenamiento
- **Algoritmo:** SGD (Stochastic Gradient Descent)
- **Learning Rate:** 0.01
- **Épocas:** 2000
- **Batch Size:** 32
- **Train/Test Split:** 80/20
- **Loss Function:** Cross-Entropy
- **Seed:** 42 (reproducible)

### 3. Performance del Modelo v6
```
Training Accuracy:  68.70%
Test Accuracy:      75.86% ✅
Training Loss:      1.0271
Validation Loss:    0.9442
Test Examples:      29 (válido estadísticamente)
```

## 🔍 ANÁLISIS TÉCNICO

### ¿Por Qué O(log n) es Crítica?

1. **Características Distintivas:**
   - Algoritmos Divide & Conquer: merge sort, quick sort, heap sort
   - Búsquedas en estructuras: BST, segment trees, binary indexed trees
   - Features características: HIGH recursion + HIGH nested_depth

2. **Facilidad de Discriminación:**
   - O(1): `[0, 0, 1]` → Trivial identificar
   - O(log n): `[2, 1, 3]` → Muy clara
   - O(n): `[1, 0, 1]` → Muy clara
   - O(n²): `[2, 0, 2]` → Clara

3. **Impacto en Entrenamiento:**
   - v2: O(log n) = 22% → Modelo no aprende bien
   - v6: O(log n) = 38% → Modelo aprende perfectamente

### ¿Por Qué v7 Falló? (54.55%)

**Intento:** Agregar 20 O(1) nuevos
**Problema:** v2 base contenía demasiados O(n)

```
v6 (FUNCIONA):
  O(log n): 55 (38%)
  O(n):     36 (25%)  ← BALANCEADO

v7 (FALLA):
  O(log n): 55 (33%)
  O(n):     52 (31%)  ← DESBALANCEADO
```

**Lección:** No se puede agregar O(1) sin remover O(n) del dataset.

## 💡 LECCIONES APRENDIDAS

### 1. Balanza de Dataset vs Cantidad
- **v5 y v6:** 144 algoritmos cada una
- **Diferencia:** v6 es 27.58% mejor solo por distribución
- **Conclusión:** Balance supera cantidad sin importar tamaño

### 2. Validez Estadística de Métricas
- **v1:** 93.33% en 15 test examples = ENGAÑOSO
- **v2:** 61.29% en 23 test examples = VÁLIDO
- **v6:** 75.86% en 29 test examples = SÓLIDO
- **Lección:** Tamaño del test set es crítico

### 3. Feature Engineering Limitado
- Solo 3 features numéricos disponibles
- No son altamente discriminativos por sí solos
- **Solución:** Dataset balanceado compensa limitations

### 4. Clase Crítica en Dataset
- O(log n) es la clase más importante para el modelo
- Aumentar de 17% → 38% causó +27.58% en accuracy
- Otras clases necesitan presencia mínima (5-15%)

### 5. No Agregar Sin Rebalancear
- v7 intentó agregar O(1) sin remover O(n)
- Resultado: -21.31% en accuracy vs v6
- **Lección:** Editar dataset requiere trabajo manual completo
